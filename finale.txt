SRDC SHIELD: COGNITIVE ZERO-DAY RANSOMWARE INTERCEPTOR
PROJECT REVIEW MASTER GUIDE

This document is your cheat sheet for the final project review. It explains every part of the project in simple English, paired with the technical details the reviewers will want to hear.

--------------------------------------------------------------------------------
1. THE BIG PICTURE (WHAT IS THIS PROJECT?)
--------------------------------------------------------------------------------
Simple English: 
Traditional antiviruses look for "known signatures" (like a digital fingerprint). If a hacker changes just one line of code, the fingerprint changes, and the antivirus misses it. This is called a "Zero-Day" attack. Our project fixes this by using an AI (like ChatGPT) to actually "read" what the program is trying to do before it runs. If the program behaves like ransomware, we block it—even if the world has never seen it before.

Technical Explanation:
Our project implements a "Semantics-based Ransomware Detection and Classification (SRDC)" architecture. Instead of relying on static hash signatures, we perform static behavioral analysis. We extract the semantic intent of the binary and feed it into a fine-tuned GPT-2 Large Language Model. We intercept threats directly at the browser level using a custom Chrome Extension before the file even touches the user's hard drive.

--------------------------------------------------------------------------------
2. THE TWO-LAYER DEFENSE SYSTEM
--------------------------------------------------------------------------------
Simple English: 
To make the system fast and perfectly safe, we use two checkpoints. 
Layer 1 asks a global database, "Have you seen this exact file before?" If yes and it's bad, block it instantly. If the database says "I don't know" (a Zero-Day), it moves to Layer 2, which is our custom AI brain.

Technical Explanation:
- Layer 1 (Signature Match): We compute the SHA-256 hash of the downloaded file and query the VirusTotal API. If 3 or more vendor engines flag it, we block it.
- Layer 2 (Cognitive Semantic AI): If VirusTotal returns clean or "not found", the file enters our zero-day pipeline. We statically parse the Portable Executable (PE) headers to extract behavioral intents without executing the malware (100% safe sandboxing).

--------------------------------------------------------------------------------
3. WHAT DOES THE AI ACTUALLY LOOK AT? (THE 7 FEATURES)
--------------------------------------------------------------------------------
Simple English: 
We don't run the virus to see what it does. Instead, we look at the program's "blueprint" (imports and strings) and extract 7 specific clues. For example, if a program imports "CryptEncrypt" (to lock files) and looks for the "Windows Startup Registry" (to run every time the PC turns on), our AI knows it's ransomware. 

Technical Explanation:
We use the `pefile` library to perform static extraction of 7 distinct feature channels:
1. API Calls (e.g., kernel32.dll functions)
2. Dropped Files
3. Registry Modifications (e.g., HKEY_CURRENT_USER)
4. File Operations
5. File Extensions (e.g., .exe, .tmp)
6. Directory Enumerations
7. Embedded Strings
These features are translated from raw code into plain-English behavioral sentences (e.g., "opened registry HKEY_LOCAL_MACHINE") so the NLP model can understand the intent.

--------------------------------------------------------------------------------
4. THE AI MODEL (MAX-POOLING CLASSIFIER & GPT-2)
--------------------------------------------------------------------------------
Simple English: 
Older versions of this AI just mashed all 7 clues into one giant paragraph, which confused the AI because important details got buried. We upgraded the architecture to look at all 7 clues independently. We use a model called GPT-2 (the grandfather of ChatGPT). We also built two models: one tells us IF it's ransomware, and the second tells us EXACTLY what family of ransomware it is (like CryptoWall or Locker).

Technical Explanation:
We utilize `zhouce/RDC-GPT` (a domain-specific fine-tuned GPT-2). 
Architectural Upgrade: Instead of flat concatenation (which causes context limit truncation and semantic bleeding), our final Phase 2 model uses a hierarchical `MaxPoolingClassifier`.
- It tokenizes the 7 feature channels completely independently.
- It processes them through GPT-2, generating 7 parallel sequences of embeddings.
- We apply `AdaptiveMaxPool1d` across the sequence dimension (Compression Ratio = 64). This compresses the sequence while retaining the most extreme activation features (the "loudest" semantic signals).
- We flatten the 7 compressed channels and pass them through a fully connected Linear layer.
- Model 1 (Binary): Outputs Goodware vs Ransomware.
- Model 2 (Multiclass): Outputs the specific ransomware family (12 possible classes).

--------------------------------------------------------------------------------
5. THE CHROME EXTENSION (THE FRONTEND INTERCEPTOR)
--------------------------------------------------------------------------------
Simple English: 
The user installs our Chrome Extension. When they download a file, the extension pauses the download at the very last millisecond before it saves to the computer. It asks our AI backend, "Is this safe?" If it's safe, the download finishes. If it's ransomware, the extension flashes a warning, cancels the download, and forcefully deletes any trace of it from the disk.

Technical Explanation:
We built a Manifest V3 Service Worker. It listens to the `chrome.downloads.onCreated` event.
- It immediately calls `chrome.downloads.pause()` to freeze the file in a `.crdownload` state.
- It sends an async `fetch` POST request to our local Flask backend.
- We implemented a Keep-Alive heartbeat (`setInterval` pinging `chrome.runtime.getPlatformInfo()`) so Chrome doesn't kill the background script during the heavy ~100 second CPU AI inference.
- If the Flask backend returns "blocked", the extension calls `chrome.downloads.cancel()` and `chrome.downloads.removeFile()` to aggressively purge the threat from the local disk.

--------------------------------------------------------------------------------
6. THE LOCAL FLASK BACKEND (THE SCANNING ENGINE)
--------------------------------------------------------------------------------
Simple English: 
This is the hidden server running on the user's computer. It holds the massive 500MB AI models in its memory so it can scan files instantly without uploading the user's private files to the cloud.

Technical Explanation:
A Python Flask server acts as the middleman. 
- On startup, it preloads the ~500MB `.pth` weights for both models directly into CPU memory (`torch.device("cpu")`) to guarantee low-latency inference.
- It implements secure ZIP archive extraction (recursively scanning nested executables and cleaning up the sandbox temp folder afterward).
- It returns a JSON response containing the verdict, confidence percentages, and plain-English explanations of *why* it flagged the file (e.g., "Imports CryptEncrypt, consistent with file encryption behavior").

--------------------------------------------------------------------------------
7. WHY IS OUR PROJECT UNIQUE / BETTER?
--------------------------------------------------------------------------------
If the reviewers ask, "Why is this special?", tell them:
1. **True Zero-Day Detection:** We don't rely on databases. By treating computer code like a human language, our NLP (Natural Language Processing) AI can deduce malicious *intent* from unseen malware.
2. **Pre-Disk Interception:** Most antiviruses let the file download, and *then* quarantine it. We pause the network stream in the browser, meaning the executable never formally exists on the OS filesystem to be accidentally clicked.
3. **Privacy-Preserving Local Inference:** We run the massive GPT-2 LLM entirely locally on the user's CPU. User files are never uploaded to a cloud server for AI scanning, preserving 100% data privacy.
4. **Independent Channel Architecture:** Our upgraded Phase 2 MaxPooling model fixes the "information bottleneck" of older models by processing PE features as 7 independent neural channels.
